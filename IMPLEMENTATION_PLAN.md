Branch `site-update/gemis-stories`. Written at Phase 0, before any site change.
Sources of truth: the brief, `GEMIS_case_study_videos.md`, the implementation
prompt, and the existing repository (which decides the look).

## Phase 0 audit — what is actually here

The prompt expects `_project/assets-incoming/`. **That folder does not exist.**
The two "Project Assets" commits (`043bc80`, `a22a358`) put all 28 video files in
the **repository root** instead. Following the repo rather than the prompt, as the
prompt itself instructs, the files are moved to `assets/video/case-studies/`.

| `videos/` — 7 × (`_web.mp4`, `_web.webm`, `_thumb.jpg`) | **All 21 present**, in repo root | Move to `assets/video/case-studies/` |

`facts.md` being absent decides three things by the prompt's own fallback rules:

1. **Product spelling is `ManaGEM`** — "If `facts.md` is silent, use ManaGEM to
   match the videos, and log it."
2. **No metric is publishable.** The WasteMart "six hours a week" and ManaGEM
   "nine days to two" figures carry `data-tbc`.
3. **No ManaGEM free-trial CTA**, since nothing confirms a live trial.

### Repository

- 24 root `.html` pages; header and footer markup is **duplicated per page**, with
  no include or injection mechanism. Every nav change is a 24-file edit.
- `assets/css/site.css` (the corporate stylesheet), `studio.css`, `style.css`.
- `assets/js/site.js` drives nav, mega-menu, scroll reveal and counters.
- `.nojekyll` **exists**, so underscore folders would be served. No `_project/`
  folder is created on this branch, so nothing new is exposed — but note that the
  29 MB of masters committed to root on `main` are already publicly reachable.
- Four redirect stubs already exist: `solutions.html`, `work.html`, `managem.html`,
  `brand-studio.html`.
- `gemis-site-standalone.html` is generated by `tools/build-site-standalone.py` and
  must be regenerated whenever a root page or `site.css` changes.

### Design tokens — the brief conflicts with the repository

The brief and prompt both specify Deep Navy `#0F2D5E`, Primary Blue `#1A56A0`,
Cormorant Garamond and DM Sans, describing them as "already in the CSS".

**They are not. All four appear zero times in `assets/css/site.css`.** The live
site uses `--navy: #1f2557`, `--navy-deep: #161b40`, and one family, Archivo Var.

Three rules in the prompt point the same way, so the repository wins:

- "If either conflicts with what you find in the repo, follow the repo and record
  the difference."
- "Do not redesign… keep the palette, fonts… already in the CSS."
- Phase 7: "no new web-font families."

Adopting the brief's tokens would be a redesign and would add two font families.
The build uses the repository's tokens. Logged in `IMPLEMENTATION_NOTES.md` as the
single largest deviation from the brief, for sign-off.

## Assumptions

- Canonical base is `https://sphamandla-designer.github.io/gemis-site/`, read from
  the existing canonical tags, so `{BASE_URL}` resolves to
  `https://sphamandla-designer.github.io/gemis-site/assets/video/case-studies/`.
  The videos file suggests `https://gemis.co.za/media/case-studies/`; the site is
  not served there yet, so schema uses the address the files are actually at.
- Videos are self-hosted from the repo. At 0.9–1.5 MB each and `preload="none"`,
  nothing loads before a click.
- Burned-in captions mean no `.vtt` files; missing caption files are not an open
  item, per the prompt.
- `industries.html` stays live, out of the main nav, linked from the footer.
