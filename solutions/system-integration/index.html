System integration

Systems that share information,
so nobody types it twice.

GEMIS connects the systems a business already runs — accounting, ERP and CRM platforms, payment providers, authentication services and third-party APIs — so information moves between them without retyping, exports or manual hand-offs.

The situation

When information moves by hand

Each time the same information is entered into a second system, the business pays for it twice and creates a chance for the two to disagree. Over time the hand-offs become someone’s job, and the errors someone’s problem.

Signs you may recognise

  • Invoices are retyped from one system into accounting.
  • Exports are emailed and imported by hand.
  • Payments are confirmed by checking a statement.
  • Month-end reconciles figures that should already agree.

What GEMIS delivers

An integration layer, not a tangle of exports

What GEMIS puts in place when it connects systems.

  1. 01

    Mapping the flow

    Every hand-off recorded: what moves, between which systems, when and why.

  2. 02

    One source per fact

    Each piece of information given one authoritative system; the others read from it.

  3. 03

    Supported interfaces

    Connections through each system’s own API or interface, not fragile copies.

  4. 04

    Failure handling

    Scheduling, duplicate checks, logs and alerts, so a failed transfer is noticed.

  5. 05

    Monitoring and maintenance

    Integrations watched and adjusted when a connected system changes.

  6. 06

    Documentation

    A written account of what connects to what, for whoever maintains it next.

Questions

Common questions

The questions that come up first about System integration. Anything not answered here is worth raising in a discovery conversation.

01Which systems can you connect?+

Most systems that offer a supported way in, such as an API, a database interface or a scheduled file exchange. Our case studies include an SAP financial feed, accounting, and links to insurers and manufacturers. Each system is assessed before we commit, because what is possible depends on the interfaces it provides.

02What happens if an integration fails?+

It is designed to be noticed. For Trans Hex, the SAP import runs on a schedule, skips duplicates, logs every run and emails the team if anything fails. Comparable checks are designed into each integration.

03Which system should own the data?+

That is the first question we answer. Each piece of information gets one owner and the others read from it. It is a business decision as much as a technical one, and it is made before anything is connected.

04What happens when a connected system is updated?+

A change on either side can affect an integration, which is why integrations are monitored and maintained rather than left alone. Under an ongoing support arrangement, updates are checked and the connection adjusted as needed.

05Can you connect a system that has no API?+

Sometimes — through a database connection or a scheduled file exchange, for example — though these are less robust, and some systems cannot be connected safely. We say which applies after reviewing the system.
